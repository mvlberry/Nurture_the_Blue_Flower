# 90 秒蓝花挑战：设计说明

## 目标

把现有的线性点击演示改造成一局 90 秒、可以反复挑战最高分的单人竞技小游戏，同时保持纯静态页面和“养育蓝色花朵”的主题。

## 布局

桌面端使用固定横向三栏：左侧为主要像素花园，中间为行动控制台，右侧为比赛数据。标题和状态条只占很薄的一行，不再让画布、数值与按钮上下堆叠。宽度低于 760px 时才切换为移动端纵向布局。

## 竞技循环

- 每局 90 秒，从相同初始状态开始。
- 咖啡快速增加成长，但消耗精力并提高躁动；躁动过高会持续伤害生命。
- 巧克力提供较高基础分和连击收益，但成长效率低于咖啡。
- 陪伴恢复生命、降低躁动，几乎不增加成长。
- 三类突发事件分别需要咖啡、巧克力或陪伴处理。及时选择正确行动会提高连击和分数；超时或误操作会扣除生命并清空连击。
- 精力自动恢复，各行动拥有独立冷却时间，阻止无脑连点。
- 成长达到 100 时蓝花盛开并获得时间奖励，但玩家仍需守护花朵直至回合结束。
- 生命归零会提前失败。回合结束按成长、生命、剩余精力、事件处理和连击结算，给出 C/B/A/S 评级。

## 数据与边界

所有状态都保存在浏览器内存中；历史前五名使用 `localStorage` 保存。存储内容损坏、禁用或不可写时，游戏仍能正常运行，只是不持久化榜单。页面不依赖后端、构建工具或框架，可直接部署到 GitHub Pages。

## 验证

验证桌面端三栏布局、移动端断点、三种行动的成本与冷却、事件成功/失败、躁动伤害、盛开奖励、生命归零、90 秒结算、评级和本地榜单。
